# Aseprite skill routing

The machine-readable [`catalog.json`](catalog.json) is generated by `generate_catalog.py`. Each
skill stays independently distributable; families organize discovery without introducing shared
runtime instructions.

## Overlap boundaries

- Use `aseprite-concept-to-sprite` to derive a concrete sprite specification from reference art;
  use `aseprite-sprite-production` after the specification is known.
- Use `aseprite-animation-review` to diagnose completed motion and
  `aseprite-animation-cleanup` to correct established frames. State-family skills such as
  platformer, top-down, directional, and fighting-game production own their domain contracts.
- Use `aseprite-palette-design` to construct palette roles, `aseprite-color-variant-production` to
  make controlled remaps, and `aseprite-palette-cycle-production` for indexed motion.
- Use `aseprite-tileset-production` for a general tile family, `aseprite-autotile-authoring` for
  adjacency completeness, and `aseprite-tile-metadata-authoring` for engine properties.
- Use `aseprite-ui-sprite-production` for general interface assets,
  `aseprite-nine-slice-ui-production` for scalable panels, and
  `aseprite-rpg-icon-set-production` for coherent inventory or ability sets.
- Use `aseprite-engine-export-profile` to define a handoff contract, `aseprite-game-export` to
  produce one asset's deliverables, and `aseprite-release-asset-audit` for final set-wide evidence.
- Use `aseprite-character-animation-set` for a complete state family and
  `aseprite-modular-character-production` when independently composited parts are the central
  constraint.

Run `python aseprite/skills/generate_catalog.py` after adding, removing, or renaming a skill, then
review the resulting family and recommended tool profile.
